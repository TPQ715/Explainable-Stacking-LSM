# Explainable-Stacking-LSM
R implementation of an explainable Stacking ensemble framework for landslide susceptibility mapping.
## Overview

This repository contains the R code used to implement the machine-learning and Stacking ensemble framework for landslide susceptibility mapping described in the associated study.

The modeling workflow includes four base learners—Random Forest (RF), Logistic Regression (LR), Extreme Gradient Boosting (XGBoost), and Support Vector Machine (SVM)—followed by a Stacking ensemble framework. The repository also provides code for model evaluation, comparison, external prediction, and SHAP-based model interpretation.

A lightweight quick-test workflow is provided to allow users to verify that the main modeling pipeline can run successfully without executing the complete analysis.

## 3. Recommended Running Order

To ensure that all intermediate model objects and results are generated correctly, the scripts should be executed in the following order.

### Step 1: Base Learners

Run the four base-learning models first:

1. **Random Forest (RF)**
2. **Logistic Regression (LR)**
3. **XGBoost**
4. **Support Vector Machine (SVM)**

Each base learner should be successfully trained and evaluated before proceeding to the Stacking stage.

### Step 2: Stacking Framework

After all four base learners have been successfully executed, run the:

**Stacking Framework Code**

The Stacking workflow integrates the predictions generated by the base learners to construct the final ensemble model.

The code for **external prediction** is also included in the **Stacking Framework Code**. Users who wish to apply the trained model to external data should refer to the corresponding section of this script.

### Step 3: Comparative Analysis

After completing the base learners and Stacking model, run:

**Comparative Analysis of Different Models**

This part of the code is used to compare the predictive performance of the individual machine-learning models and the Stacking ensemble model.

The recommended overall workflow is therefore:

```text id="9eslzr"
Input Data
    |
    v
Base Learners
    |
    +-- Random Forest
    +-- Logistic Regression
    +-- XGBoost
    +-- Support Vector Machine
    |
    v
Stacking Framework
    |
    +-- Ensemble Modeling
    +-- Model Interpretation
    +-- External Prediction
    |
    v
Comparative Analysis of Different Models
    |
    v
Model Evaluation and Results
```

Two lightweight test files are provided:

- `quick_test`
- `quick_test_1`

## 5. Data Availability

The quick-test data provided in this repository are intended to demonstrate the functionality of the code and facilitate rapid testing of the modeling workflow.

The **original dataset used for the full analysis is not included in this repository**.

Researchers who require access to the original data for academic and reproducibility purposes may contact the corresponding author of the associated manuscript.

When using a different dataset, users should ensure that:

- the response variable is correctly formatted;
- predictor names are consistent with those expected by the scripts;
- categorical variables are correctly defined as factors;
- continuous variables are correctly defined as numeric variables;
- missing values are appropriately handled; and
- the training and prediction datasets contain consistent predictor variables.

## 6. External Prediction

The external prediction procedure is included in the **Stacking Framework Code**.

Before applying the trained model to a new dataset, users should ensure that the external prediction data are consistent with the training data in terms of:

- factor levels;

- predictor structure.

## 8. Reproducibility

To improve reproducibility, users are recommended to:

1. Use a consistent R and package environment.
2. Set a random seed before data splitting, cross-validation, and model tuning.
3. Maintain identical variable names and data types throughout the modeling workflow.
4. Use the same resampling strategy for candidate models used in the Stacking framework.
5. Record package versions using:

```r id="ggxf7n"
sessionInfo()
```

Users should also avoid changing variable names or predictor structures after a model has been trained, because previously saved model objects may require the original variables used during model development.

---

## 9. Important Notes

Please note the following before running the complete workflow:

- Run the scripts in the recommended order.
- Do not proceed to the Stacking stage until all required base learners have been successfully executed.
- Ensure that the outcome variable contains the required classes for classification.
- Check categorical predictors carefully before model training.
- Avoid treating continuous predictors as categorical factors.
- Ensure that the same predictor names are used during model training and prediction.
- Saved tuning or model objects may not be compatible with datasets whose variable names or structures have subsequently been changed.
- The quick-test workflow is intended to verify code functionality rather than reproduce the final numerical results reported in the manuscript.
- Full model training, hyperparameter optimization, cross-validation, and SHAP analysis may require substantially more computational time than the quick-test workflow.

## 10. Troubleshooting

If an error indicates that an R package is missing, install the required package before rerunning the corresponding script.

For example:

```r id="e9qcr7"
install.packages("ggbeeswarm")
```

If an error reports missing predictor columns, check the variable names in the input dataset:

```r id="d8t7bi"
names(data)
```

The predictor names and variable types used for prediction should be consistent with those used during model training.

If a saved model object is incompatible with a modified dataset, the corresponding model may need to be retrained using the current data structure.
